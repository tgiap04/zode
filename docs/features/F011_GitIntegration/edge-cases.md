# Edge Cases — F011_GitIntegration

| Scenario                                                                                                 | What Happens                                                                                                                                                | User-Facing Message                                                                                      |
| -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Developer tries to commit while unresolved merge conflicts remain unstaged                               | Commit is blocked entirely; nothing is written to the repository                                                                                            | "There are still conflicts. You must stage these before committing"                                      |
| Developer tries to commit with nothing staged and no tracked changes to auto-stage                       | Commit is blocked; no empty commit is created                                                                                                               | "No changes to commit"                                                                                   |
| Developer applies, pops, or drops a stash entry that has changed (or vanished) since the list was loaded | The operation is aborted rather than acting on the wrong stash entry, and the Commit View closes                                                            | "Stash has changed, not applying" / "Stash has changed, pop aborted" / "Stash has changed, drop aborted" |
| Developer switches branches while uncommitted changes would be overwritten by the checkout               | `git checkout` itself refuses the switch; nothing is checked out or lost                                                                                    | "Failed to change branch" (dialog showing git's underlying error)                                        |
| Developer discards changes on a file that was never committed (newly created/untracked)                  | Instead of a git checkout, the app asks to confirm deletion and then trashes the file via the OS trash, rather than reverting to a nonexistent HEAD version | "Trash {filename}?" confirmation prompt                                                                  |
| Any underlying git process (stage, unstage, stash, commit, checkout, push) exits with a non-zero status  | The failure is captured with the process's stderr and shown as a dialog; no partial state change is applied and no automatic retry happens                  | "Failed to {stage/unstage/stash/commit/checkout} paths/files: {git's own error text}"                    |
