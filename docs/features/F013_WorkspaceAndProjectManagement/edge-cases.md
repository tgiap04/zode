# Edge Cases — F013_WorkspaceAndProjectManagement

| Scenario                                                                                               | What Happens                                                                                                                                              | User-Facing Message                                                                            |
| ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Recent project's folder moved or deleted since last session                                            | Opening the recent entry fails to find the path instead of silently opening an empty/broken workspace                                                     | "This project's folder could not be found — it may have been moved or deleted."                |
| Idle timer fires while the project has an active debugger session                                      | Hibernation is deferred and retried later; nothing in the background is torn down while debugging is in progress                                          | "None — silent handling (project stays fully active)"                                          |
| Idle timer fires while a file is dirty and autosave-on-focus-change/window-change is enabled           | Hibernation is deferred and retried, avoiding an interrupted format-on-save                                                                               | "None — silent handling (project stays fully active until the save completes)"                 |
| Sidebar shows a project as "Hibernated" but its language server/scanner teardown hasn't fully finished | Any action against that project may briefly still hit live resources — the hibernated label is a lifecycle signal, not a guarantee everything has stopped | "Hibernated — will wake when opened" (informational; not a hard guarantee of full teardown)    |
| System memory runs low while several projects sit idle in the background                               | At most one eligible idle project is put to sleep per check, and a project woken by hand is protected from being re-selected right away                   | "None — silent handling (a background project may quietly go to sleep to free memory)"         |
| A project just manually reactivated is immediately eligible for the same low-memory sleep check        | The just-woken project is protected for a short grace window so it isn't put back to sleep the instant you switch to it                                   | "None — silent handling"                                                                       |
| Dev-container config specifies only one of the two paired settings it requires                         | Validation rejects the config before any build is attempted                                                                                               | "This dev container configuration is invalid — check the workspace mount and folder settings." |
| Docker/Podman isn't installed, or the image/container build fails                                      | The build is not silently skipped; the failure is surfaced instead of leaving a stale or missing image                                                    | "Failed to build the dev container — see the error for details."                               |
| Opening a folder Zode has never seen before                                                            | Language servers and certain git operations are blocked until the developer explicitly grants trust                                                       | "This folder is untrusted. Trust it to enable language features and git integration?"          |
| Deleting a git worktree from the picker                                                                | The worktree is detached from the project's list, but the folder and its contents remain untouched on disk                                                | "Worktree removed from this project (folder left on disk)."                                    |
