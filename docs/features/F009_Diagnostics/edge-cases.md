# Edge Cases — F009_Diagnostics

| Scenario                                                                                                      | What Happens                                                                                                    | User-Facing Message                                                                            |
| ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Developer triggers "open current file diagnostics" with no file focused, or an unsaved scratch buffer focused | The command silently does nothing — no tab opens                                                                | "None — silent no-op"                                                                          |
| Developer opens the project-wide diagnostics view right after a project wakes from hibernation                | A banner appears above the list, and the counts shown may not be fully up to date yet                           | "Project re-indexing after waking — some counts may be stale"                                  |
| A file's error/warning badge in the file tree is left over from before the project went idle                  | The badge shows dimmed rather than in its normal color, until that file's diagnostics are freshly re-verified   | "None — visual dimming only, no text message"                                                  |
| Two diagnostic updates for the same files arrive within 50ms of each other                                    | Both updates are merged into a single refresh instead of doing the work twice                                   | "None — invisible to the user, no message"                                                     |
| Developer clicks the status-bar activity indicator while multiple language-server problems are queued         | Only the single most recent error or warning is shown; the rest stay queued for the next click                  | "(server name) Error: {last error message}" or "(server name) Warning: {last warning message}" |
| A language-server health update arrives with no accompanying message text                                     | That update is dropped without ever being shown to the developer                                                | "None — silent, no message shown"                                                              |
| Developer dismisses the status-bar error message when there is no recorded formatting failure                 | Nothing happens — the dismiss action is a no-op                                                                 | "None — silent no-op"                                                                          |
| Developer records an ETW performance trace (Windows) and the recording session fails partway through          | The in-progress trace's kernel buffers are released automatically; no partial/corrupt trace file is left behind | "None — cleanup is automatic; no explicit error text observed in code"                         |
