## Overview

**Priority:** P1 · **Build state:** 🔴 RED → GREEN for tests · **Depends on:** Phase 9

Fix the tests that the deletion legitimately broke, and sweep the docs — which are **not cosmetic here**: the mdbook preprocessor validates every action reference and every JSON settings snippet in `docs/`, and the `check_docs` CI job fails on any dangling one.

The `expected_namespaces` assertion deferred from Phase 8 is updated here, on purpose, only after the action list has been regenerated.

## Key Insights

- **`zed.rs:5077` `test_action_namespaces`** asserts `cx.all_action_names()` namespaces match a hardcoded list at `:5110-5198` including `"copilot"`, `"collab"`, `"zeta"`, `"agent"`, `"assistant"`, `"channel"`. It is the best canary for a leftover registered action. Update it **from the regenerated dump**, and treat an unexpected surviving namespace as a real finding.
- **`settings_store.rs:2871-2872`** literally asserts `user_schema_str.contains("\"auto_update\"")`. Hard fail once the key is gone.
- **`docs_preprocessor` validates docs against live code twice over**: `main.rs:370-390` compiles the settings schema and validates every labeled JSON block in `docs/`; `:254`, `:302`, `:193-200` resolve every `{#kb ...}` and `{#action ...}` reference and raise `PreprocessorError::ActionNotFound`. The `check_docs` CI job (`.github/workflows/run_tests.yml:636-680`) fails on either.
- `crates/docs_preprocessor/actions.json` is **not committed** — regenerated by `script/generate-action-metadata`. `load_all_actions` (`main.rs:622`) **panics** if it is missing when `CI` is set.
- `docs/src/SUMMARY.md` is **mandatory**: dangling links are a hard `mdbook build` failure. Lines `:13-28`, `:51-53`, `:165`, `:184`, `:186`, `:188` point at pages being deleted.
- The rebuild-spec artifacts under `plans/260726-1400-rebuild-spec/` and the generated `docs/system/` + `docs/generated/` describe a 240-crate workspace. They become factually wrong at Phase 4.

## Requirements

**Functional**
- `cargo nextest run --workspace` passes, with any failures traceable to the Phase 1 baseline rather than to this work.
- `mdbook build docs` succeeds; `check_docs` CI job green.
- No test silenced without justification.

**Non-functional**
- Tests deleted only when the feature they cover was deleted. Never `#[ignore]` to make the suite green.

## Architecture

```
regenerated action dump ─► expected_namespaces (zed.rs:5110-5198)
                        └─► docs {#kb} / {#action} sweep
                        └─► script/generate-action-metadata → actions.json (CI)

deleted settings keys   ─► settings_store.rs test fixtures + schema assertions
                        └─► docs JSON snippet validation

deleted crates          ─► docs/src/{ai,collaboration}/**, SUMMARY.md
                        └─► docs/system/*, docs/generated/*  (regenerate, Phase 11+)
```

## Implementation Steps

### 10a. Tests

1. Regenerate the action metadata the docs pipeline needs:
   ```sh
   script/generate-action-metadata
   ```
2. Update `expected_namespaces` (`zed.rs:5110-5198`) **from the regenerated dump**, not by deleting the entries you expect to be gone. Remove `"agent"`, `"assistant"`, `"assistant2"`, `"auto_update"`, `"channel_modal"`, `"collab"`, `"collab_panel"`, `"copilot"`, `"edit_prediction"`, `"inline_assistant"`, `"agents_sidebar"`, `"zeta"` — **but only those the dump confirms are gone.** Anything still present is a finding: an action is still registered somewhere.
   > `"context_server"` should **remain** — the crate survives.
3. `settings_store.rs:2871-2872` — replace the `auto_update` schema assertion with a key that still exists.
4. Remove test fixtures referencing deleted keys: `settings_store.rs:2035`, `:2109`; delete the test-only `impl Settings for AutoUpdateSetting` `:1634-1645`.
5. `zed.rs:5593` `test_disable_ai_crash` — delete; the `disable_ai` key is gone.
6. Run the suite and diff against the Phase 1 baseline **by test name** (red team finding 7 — a summary-tail diff cannot support this phase's own acceptance bar):
   ```sh
   cargo nextest list --workspace > research/post-deletion-test-names.txt
   cargo nextest run --workspace --no-fail-fast --message-format libtest-json \
     > research/post-deletion-tests.json 2> research/post-deletion-tests.log

   # tests that vanished — every one must belong to a deleted crate
   comm -23 <(sort research/baseline-test-names.txt) <(sort research/post-deletion-test-names.txt)

   # tests that now FAIL but previously passed — must be empty
   ```
   Classify every delta into exactly one bucket: **(a)** disappeared with its crate, **(b)** deleted by us on purpose, **(c)** newly failing. Bucket (c) must be empty. **Do not `#[ignore]` anything to close a gap.**

### 10b. Docs

7. Delete the ~27 files listed above. **Keep `remote-development.md`.**
8. `docs/src/SUMMARY.md` — remove every link to a deleted page (`:13-28`, `:51-53`, `:165`, `:184`, `:186`, `:188`). Dangling links are a hard build failure.
9. Sweep for dangling action/keybinding references across all remaining docs:
   ```sh
   rg -n '\{#kb |\{#action ' docs/src/ | grep -Ef <(sed 's/^/:/' research/removed-actions.txt)
   ```
   Rewrite or remove each hit.
10. Sweep for JSON settings snippets containing deleted keys — the preprocessor validates them against the live schema:
    ```sh
    rg -n '"agent"|"language_models"|"edit_predictions"|"collaboration_panel"|"auto_update"|"calls"' docs/src/
    ```
11. Regenerate the three generated docs: `all-actions.md`, `reference/all-settings.md`, `reference/default-key-bindings.md`.
12. Build the book:
    ```sh
    mdbook serve docs        # or: mdbook build docs
    ```
    Per `docs/README.md:14`, `script/generate-action-metadata` must have run first (step 1).
13. Update `docs/README.md` and `CONTRIBUTING.md` where they reference removed subsystems.

## Risk Assessment

| Risk | Impact | Mitigation |
|---|---|---|
| `expected_namespaces` edited to "make it pass" | Loses the canary; a leftover registered action ships | Step 2 requires deriving from the dump and investigating surprises |
| A test `#[ignore]`d to close the suite | Green build hiding a real regression — explicitly forbidden by the project rules | Step 6 states it; success criteria assert it |
| `actions.json` missing in CI | `load_all_actions` **panics** when `CI` is set | Step 1 regenerates it; confirm the CI step still runs `script/generate-action-metadata` |
| Docs JSON snippet left with a deleted key | `check_docs` CI failure, discovered late | Step 10 sweeps explicitly |
| `remote-development.md` deleted by reflex with the other cloud docs | Documentation lost for a feature that survives | Called out in three places in this phase |
| Stale `docs/system/*` treated as truth by a future session | Wrong decisions built on fiction | Step 14/15 mark and schedule regeneration |
